# 前端后台模板设计

Vue 和 React 各提供一套独立的 Vite + TypeScript 项目。每套模板自带登录页、后台布局、菜单、路由守卫和无权限页。AI 检测用来演示业务模块如何接入，可从任一模板中直接移除。

## 后台设计基线

把视觉焦点留给当前任务。Vue 和 React 遵循同一份设计规则，由各自的组件库实现。

- 侧栏负责模块导航，顶栏承载账号等全局操作。保持导航区域的视觉权重低于主内容区，并清楚标出当前页面和键盘焦点。
- 页面标题和操作栏的位置保持一致。每个页面优先突出一项主要操作，例如在检测任务页将「新建任务」放在标题右侧，并按权限展示。
- 列表优先展示判断和操作所需的信息。任务状态使用文字标签，可配合颜色提示。
- 检测任务作为交互示例。用户可从列表打开详情预览，查看检测结果或失败原因，关闭后回到原有的筛选、分页和滚动位置。

页面结构确定后再细化配色、字体和间距。

## UI 技术选型

| 模板 | 后台组件库 | 页面样式 |
| --- | --- | --- |
| Vue | Element Plus | Tailwind CSS |
| React | Ant Design (`antd`) | Tailwind CSS |

表单、表格、菜单、弹窗和消息反馈优先使用各自的组件库。组件颜色、圆角等外观通过组件库的主题配置调整。Tailwind CSS 用于页面布局、间距和响应式排版，由两套模板各自配置。首版关闭 Tailwind Preflight，接入时检查表单、表格和弹窗的样式。

## 目录草案

以下目录分别位于 `frontend/vue/src/` 和 `frontend/react/src/`。两套项目各自拥有源码、API 客户端、样式、依赖和锁文件。

| 职责 | Vue | React |
| --- | --- | --- |
| 应用入口与路由 | `main.ts`、`App.vue`、`router/` | `main.tsx`、`app/`，由 `app/` 装配路由和应用级 Provider |
| 路由页面 | `views/` | `pages/` |
| 后台布局 | `layouts/` | `layouts/` |
| 业务功能 | `features/auth/`、`features/roles/`、`features/detection/` | `features/auth/`、`features/roles/`、`features/detection/` |
| 通用基础 | `components/`、`lib/http.ts`、`styles/` | `components/`、`lib/http.ts`、`styles/` |

页面负责组合布局和业务功能。功能专属的组件、API 和类型放在对应的 `features/` 模块内。`auth` 负责当前用户和登录状态，`roles` 实现角色管理页面的业务操作。任一模板移除检测功能时，只需移除检测模块和对应页面、路由，后台仍可通过首页进入。

## 页面与权限草案

| 路径 | 页面 | 访问规则 |
| --- | --- | --- |
| `/login` | 登录 | 公开 |
| `/change-password` | 首次改密（正式版） | 使用有效临时密码登录后进入 |
| `/` | 工作台 | 登录后可访问 |
| `/detections` | 检测任务 | 登录后可查看后端返回的记录。操作员和管理员可提交任务 |
| `/admin/roles` | 角色管理 | 管理员可修改演示账号 `analyst` 的角色 |
| `/admin/users` | 账号管理（正式版） | 管理员可查询、创建、停用账号，调整角色和重置密码 |
| `/admin/audit` | 操作审计（正式版） | 管理员可分页查询账号管理和人工重试记录 |
| `/403` | 无权限 | 提供返回首页的入口 |

菜单根据路由可见规则生成，守卫用同一组规则处理直接访问。未登录进入受保护页面时先到登录页，登录成功后返回有权访问的原页面。已登录但权限不足时跳转到 `/403`。页面和按钮使用后端返回的角色呈现相应操作，角色授权和记录可见范围由后端校验。现有演示接口详见 [权限与检测接口契约](../contracts/detection.md)。

路由建议采用 Vue Router 的元信息和导航守卫，以及 React Router 的嵌套路由和权限布局。模板继续沿用 `/api/` 同源请求。

正式部署的登录页使用模板自带的本地账号。两套前端使用同源登录会话，恢复页面时重新读取当前用户及角色。登录或刷新时，如果当前用户需要改密，将其引导到改密页。设置新密码后返回登录页。有权访问的原页面可在重新登录后恢复。详见[正式登录与会话](../contracts/detection.md#正式登录与会话)。

管理后台的账号列表展示登录名、角色与启用状态。创建或重置成功时，在当前操作结果中展示临时密码及有效期。停用或降权被拒绝时，在操作处显示后端返回的管理员保护提示。

## 工作台首页

- 侧栏按权限展示「工作台」和「检测任务」。管理员通过侧栏进入正式版「账号管理」或样本演示的「角色管理」。顶栏的账号菜单提供退出入口。
- 启用检测模块时，操作员和管理员的首页首屏突出「上传并检测」。进入后选择数据、确认提交，提交成功后显示任务状态。
- 「查看历史结果」放在主按钮旁，进入已有的检测任务页 `/detections`，从列表打开已完成任务的结果。查看者从这个入口查看有权访问的结果。
- 首页下方保留最近检测任务，显示任务名称、状态和创建时间。现有演示以样本编号标识任务，沿用 `GET /api/detections` 的倒序结果，最多返回 20 条可见任务。
- 移除检测示例时，一并移除检测菜单、上传与历史结果入口和最近任务区。工作台继续提供其余有权访问的入口。

## 提交检测任务

- 一条任务接收一个数据文件，支持装有图片的 ZIP 包或一个视频。选择文件后，显示文件名和任务类型「图片包」或「视频」，提交前可替换。
- 操作员填写任务名称并点击「开始检测」。界面先显示「正在校验文件」，校验完成后显示已传大小、总大小和上传进度。容量不足时，在传输前显示磁盘空间不足的提示。
- 网络中断后，从服务端确认的位置继续。刷新或重新打开页面后，可重选原文件恢复有效的上传会话。前端校验重选文件的大小及 SHA-256 摘要。校验不一致时，提示选择原文件或发起新上传。
- 登录会话过期时暂停上传并提示重新登录。使用同一账号且仍有提交权限时，可恢复有效的上传会话。权限已撤销时提示当前账号无法继续提交。
- 文件上传结束后自动登记任务。暂时性登记失败时可在同一上传会话内重试。上传会话过期或落盘文件摘要校验失败时提示重新上传。登记成功后显示「等待检测」，算法实际开始后显示「检测中」。上传限制和续传机制见[大文件上传与断点续传](../contracts/detection.md#大文件上传与断点续传)。

## 历史检测结果

「查看历史结果」进入检测任务页 `/detections`。表格每行对应一条任务，默认按创建时间从新到旧排列。

| 列 | 内容 |
| --- | --- |
| 日期 | 任务创建时间 |
| 任务类型 | 图片包或视频 |
| 检出项 | 检测类别摘要 |
| 任务名称 | 提交时填写的任务名称 |
| 检测结果 | 显示任务状态，已完成的任务提供「查看结果」入口 |

筛选区初稿提供日期范围、任务类型、检出项和任务名称。结果入口打开任务详情，关闭详情后回到原列表位置，并保留筛选条件和分页。

## 检测结果详情

历史列表点击「查看结果」后在右侧打开预览。顶部展示任务名称、任务类型、创建时间和检出项摘要。关闭预览后保留列表的筛选、分页和滚动位置。

- 图片包任务按图片浏览标注预览和检出明细。结果为空时显示「未检出」。
- 视频任务播放标注预览视频。点击检出时间点跳到对应画面，并展示该处的检出明细。
- 原件到期清理后，已完成任务继续展示标注预览和检出明细。失败任务的原件到期后，详情保留失败原因，并提示重新上传以发起新任务。

提交成功后可查看同一条任务的状态，任务完成后进入结果预览。现有样本编号演示使用 `/api/detections`。文件上传、历史筛选和预览的数据结构见[文件检测接口草案](../contracts/detection.md#文件检测接口草案)。

## 操作审计

正式部署后，管理员通过侧栏进入「操作审计」。列表按操作时间倒序排列，列出时间、操作者、操作类型、目标及变更详情。筛选区提供时间范围、操作者、操作类型和目标。记录详情展示 `requestId`，方便关联后端运行日志。审计范围见[操作审计契约](../contracts/detection.md#操作审计)。

## 首版范围与实施顺序

1. **通用后台。** 暂定先用 Vue 验证登录、工作台、侧栏、路由守卫、403 页和角色管理。沿用现有演示的 `/api/me` 与 `/api/admin/analyst`，接入 Element Plus 和 Tailwind CSS。React 使用 Ant Design 和 Tailwind CSS 实现同一套交互与权限规则。
2. **可移除的检测示例。** 两套模板各自通过现有 `/api/detections` 提交样本编号、查看状态和结果。工作台的检测入口、最近任务和业务页面由检测模块提供，移除示例后可继续使用通用后台。第一版以两套模板均可独立运行并通过下列场景验收为目标。
3. **真实文件检测。** 按[文件检测接口草案](../contracts/detection.md#文件检测接口草案)接入 ZIP 和视频上传、历史筛选分页、图片标注预览及视频时间点跳转。联调依赖任务、结果和媒体访问接口。

## 前端测试方案

| 检查 | 首版安排 |
| --- | --- |
| 类型检查与构建 | 沿用两套模板各自的 `npm run build`。 |
| 浏览器回归 | 使用 Playwright Test，Vue 和 React 各自维护配置和用例，首版用 Chromium 跑登录、权限和样本检测流程。 |
| AI 浏览器检查 | 按需用 Chrome DevTools MCP 打开本地页面、操作表单和菜单、截图，并查看控制台和同源 API 请求。记录复现步骤和关键证据。 |
| 代码审查 | 独立运行 OpenCodeReview。参考根目录的项目规则，核查权限规则、同源 API、模板独立性和关键回归覆盖。 |

- 未登录访问受保护页面会转到登录页，登录成功后回到有权访问的原页面。
- 查看者看不到新建和角色管理入口，直接访问角色管理页会进入 403，后端拒绝越权 API 请求。
- 管理员可分配演示角色。操作员能提交样本，随后查看自己的任务状态和结果。
- 真实文件检测接入后，增加 ZIP 和视频各一条用例，验证上传、历史筛选与预览。原件清理后，从历史详情验证标注预览、检出明细和视频时间点跳转。退出预览后保留筛选、分页和列表位置。

上游文档见 [Playwright Test](https://playwright.dev/docs/intro) 和 [Chrome DevTools MCP](https://github.com/ChromeDevTools/chrome-devtools-mcp)。

## 实现验收

- 两套前端可各自复制、安装和运行。
- 未登录时直接打开受保护地址能进入登录页。已登录但越权时菜单隐藏对应入口，直接访问进入无权限页。
- 管理员可修改演示账号的角色。操作员可提交任务，查看者可浏览自己的检测记录。
- 移除检测模块及其页面、路由后，登录、首页和权限管理仍可运行。
